# 自动拓扑图（Zabbix 前端模块 `topomap`）

在 **监测 → 自动拓扑图** 下新增一个页面：创建拓扑图、按名称列表、点名称进画布预览，
「编辑拓扑图」里可对 **地图元素 / 形 / 链接** 做添加与移除，元素支持 **图片** 与 **主机**
（主机元素带问题标签、自动选择图标、默认/问题/维护/停用四套图标）。
页头还有 **自动发现**：选几台交换机当起点，读 SNMP 的 LLDP / CDP 邻居表，自动生成一张拓扑图。

数据直接读写 Zabbix 原生 `sysmaps`（`map.create` / `map.update` / `map.delete`），
所以模块里画的图和「监测 → 拓扑图」是**同一份数据**：两边都能看到、都能改。

列表 / 画布的状态也和原生一样会**记住**：在画布页切走，下次点菜单回来还是那张图；
在列表切走，点回来还是列表。

---

## 界面与操作

列表页刻意照着 Zabbix 原生 **监测 → 拓扑图** 做：左侧页头标题 + 右上角 `创建拓扑图`，
下面是可折叠的 **条件检索**（名称 + 应用 / 重设）、`名称 / 宽(px) / 高度(px) / 动作` 表格、
底部固定操作栏（`N 已选` / 导出 / 删除）。用的是主题自带的类名，深浅色都跟着主题走。

| 位置 | 元素 | 说明 |
| --- | --- | --- |
| 页头 | **自动发现** | 选起点设备 → 读 LLDP/CDP 邻居 → 自动生成一张拓扑图（详见下节） |
| 页头 | **创建拓扑图** | 弹出表单：**名称** + **应用** + **重设**；画布尺寸自动，不用填；应用后直接进入该图画布 |
| 列表页 | **条件检索** | 名称模糊过滤，`应用` 生效、`重设` 清空；点标题可收起/展开 |
| 列表页 | 表头 | 点 `名称` / `宽(px)` / `高度(px)` 排序，再点一次反向（中文按拼音） |
| 列表页 | 勾选框 | 全选 / 单选；底部实时显示 `N 已选`，`删除` 批量删除（带二次确认） |
| 列表页 | **导出** | 导出选中（未选中则全部）拓扑图为 JSON，文件名 `topomap-年月日-时分秒.json` |
| 列表页 | 名称列 | 点击进入画布，**只预览**（可缩放、平移，不可改） |
| 列表页 | 动作 → **属性** | 改名称；画布尺寸只读显示「自动（当前 宽 × 高）」；同一弹窗里可删除整张图 |
| 列表页 | 动作 → **编辑** | 直接进入该图的编辑模式 |
| 画布 | **编辑拓扑图** | 显示工具条：`地图元素: 添加/移除`、`形: 添加/移除`、`链接: 添加/移除`，右侧 `保存` / `退出编辑` |
| 画布 | 缩放 | 进入时固定 **100%**；`−` / `100%` / `+` 调缩放，`适应窗口` 做自适应缩放；工具条显示 `自动 · 当前宽 × 高` |
| 画布 | 添加地图元素 | 画布中央生成一个新组件并弹出属性窗口（类型默认「图片」，标签「新的组件」） |
| 画布 | 单击元素 | 打开「地图元素」窗口：类型（图片/主机）、标签、标签位置、主机、问题标签、自动选择图标、图标 |
| 画布 | 拖动元素 / 形 | 四个方向都能拖：画布铺满可视区域，右/下贴边时视图自动平移，左/上越界时整图外推、画布向左上生长 |
| 画布 | 链接 添加 | 依次点两个元素 → 生成链接并弹出「链接」窗口（标签/颜色/线型 + 指标） |
| 画布 | 链接 指标 | 「链接」窗口里 **带宽 / 上行流量 / 下行流量** 各可 `选择…` 从两端主机的监控项中**多选**；显示时把这些监控项的最新值**求和**、按单位换算后叠在连线中点（详见下节） |
| 画布 | 移除 | 进入移除模式后点目标即可删除（Esc 或再点一次按钮取消） |

### 自动发现（SNMP LLDP / CDP）

点页头 **自动发现** 打开弹窗：

- **主机列表**：只有配了 SNMP 接口的主机能勾，其余显示 `无 SNMP` 且勾选框禁用；
  可搜索、可「全选有 SNMP 的」，右侧实时显示 `已选 N 台`
- **发现深度**：1~4 层（默认 3），从起点设备往下 BFS 展开
- **协议**：`LLDP`（默认开）/ `CDP`（老思科设备）/ `EDP`（Extreme 设备）；
  **包含未纳管设备**（默认开，勾上后匹配不到 Zabbix 主机的邻居也会画成节点）
- **开始发现**：日志区逐行输出进度；完成后同一个按钮变成 **生成拓扑图**，并出现名称输入框
  （默认 `自动发现 YYYY-MM-DD HH:MM`）
- 生成后按 BFS 层级布局：`x = 80 + 层数 × 300`、同层竖排 `y = 80 + 行号 × 170`；
  重名自动加 ` (2)`；生成完直接进新图的画布
- **连线颜色**：自动发现生成的连线正常态是绿色 `00CC00`
- **多条连线**：同一对设备之间可以有**多条**连线（链路聚合的多个成员口、堆叠互联）；
  去重按「两端端口」而不是设备对，所以 N 个成员口生成 N 条线，每条各绑自己的端口触发器；
  LLDP 双向发现（A→B 与 B→A）上报的是同一对端口，会被合并成一条。
  画布上这 N 条线**贴近成束**、整组当**一条链路**：共用一个标签框，点任意一条都打开同一个
  「链接」对话框，编辑与移除都作用于整组（对齐 aiops）
- **邻居命名 / 地址**：匹配到 Zabbix 主机就用主机自己的名字与管理 IP；未纳管的用 `sysName`，
  `sysName` 为空时用 `chassisId`（终端 / AP / 打印机只上报 MAC），两者都没有才用上报的 IP。
  同一台设备把同一个地址回声给多个不同名字的邻居（H3C / 华为的 `lldpRemManAddr` 行为）时，
  该地址判为无效丢弃
- **图标按类型自动选**（对齐 aiops）：交换机 `Switch_(128)`、终端 / PC `Workstation_(128)`、
  服务器 `Server_(96)`、路由器 `Router_(128)`、防火墙 `Firewall_(128)`、打印机 `Printer_(128)`；
  判断依据是 sysDescr / sysName 关键词 + 对端端口是否为 MAC（MAC ⇒ 终端网卡，对应 aiops 的
  `is_distribution`）。重新发现时，老图里仍是默认 `Server_(96)` 的元素会按类型换成对应图标，
  手动改过图标的不动
- **自动关联触发器**：生成时按「端口名 + 状态类关键词」在两端的触发器里找出属于这条链路的
  端口状态触发器，绑成原生拓扑图的**链路指示器**（`linktriggers`）。该触发器报警时，
  连线和原生拓扑图都会变成红色 `DD0000`；两端都命中时只用源端（避免条数翻倍）

端口 ↔ 触发器的匹配规则（和 aiops 项目 `lldpDiscoveryService` 一致）：

| 项目 | 做法 |
|---|---|
| 关键词 | 描述里命中 `link down` / `is down` / `has changed status` / `处于关闭状态` / `链路中断` / `接口关闭` / `接口状态变化` / `端口关闭` 等 |
| 端口名 | 归一化后带字母数字边界匹配：`Gi0/0/6` ↔ `ge0_0_6` ↔ `GigabitEthernet0/0/6` 视为同一端口，且 `ge006` 不会命中 `ge0060` |
| 优先端 | 源端（发现方向扫到的一端）优先，源端没有才回退目标端 |

原理都在 `services/LldpDiscovery.php`（PHP 的 `snmp` 扩展，不需要 net-snmp 命令行）：

| 项目 | 做法 |
|---|---|
| 读邻居 | 分表 walk：`lldpRemTable`（`…2.1.4.1.1`）、`lldpLocPortId`（`…3.7.1.3`）、`lldpLocSysName`（`…3.3.0`）、`lldpRemManAddr`（`…4.2.1.3`）。**绝不 walk 整棵 `1.0.8802.1.1.2.1`**（原因见下面的 1.0.10） |
| 邻居端口 | `lldpRemPortId`（列 7）——交换机上报的是 `GigabitEthernet1/0/1` 这类接口名；只有它是 MAC（终端网卡）时才回落到 `lldpRemPortDesc`（列 8） |
| 本地端口 | `lldpLocPortId`（`3.7.1.3.<port>`）——华为的 `lldpRemLocalPortNum` 是「槽位<<16\|端口号」，不能当 ifIndex 用 |
| 本机名 | `lldpLocSysName`（`3.3.0`）——华为的 `sysName` 经常是 `(none)` |
| 邻居地址 | `lldpRemManAddr`（`4.2.1.3`）藏在索引里；支持 len=4 二进制与华为的 len=11 ASCII 点分十进制 |
| EDP 邻居 | `EXTREME-EDP-MIB`：邻居名 `1.3.6.1.4.1.1916.1.13.2.1.3`、邻居端口 `…2.1.6`；索引是 `<本地端口 ifIndex>.<邻居 id>`，本地端口再用 IF-MIB `ifName` 换名（EDP 不上报 IP） |
| OID 输出格式 | 显式设成 `SNMP_OID_OUTPUT_NUMERIC`：默认的 `IF-MIB::ifName.7` / `iso.0.8802…` 混排会截断多段索引，解析必错 |
| 自己地址 | 华为会把自身管理地址填进所有端口，按本机接口 IP 剔掉 |
| 匹配主机 | 先用 IP，再用 sysname / 主机名 / 可见名做索引匹配；匹配不上即「未纳管」（图片元素） |

**为什么要分成多次窄表 walk**：早期版本为了躲开华为 / H3C snmpd 对连续请求的限流，改成「一次
walk 整棵 LLDP-MIB 子树」，结果踩了更硬的坑 —— 子树里的 `lldpExtensions`（`1.0.8802.1.1.2.1.5`，
即 LLDP-MED）在 H3C Comware 上会让 net-snmp 的 GETBULK **永久挂死**（实测 30s 仍无返回，
`timeout -s KILL` 都杀不出结果），整轮发现就被这一台设备拖死，界面停在「扫描 xxx …」再也不动。
分表之后每张表都是毫秒级稳定返回（remTable 144 行 / 0.53s），一台设备 4 次请求、约 1s。
限流仍然靠这些约束兜底：

- 同一台设备两次请求间隔 ≥ 70ms
- 失败（超时 **或** 回了空表）按 350ms / 900ms 退避各重试一次
- 一批最多 8 台（前端每批 3 台），整批还有 **20s 时间预算**，超预算的主机标记跳过，
  不会把 nginx 的 `fastcgi_read_timeout` 顶爆变成 502
- 前端对每次 `discover` 请求再加一道 **45s 超时**：真卡住时报「扫描超时（45 秒仍无返回），
  已跳过这批设备」，而不是让弹窗一直转

错误信息分两种，指向不同原因：

- `SNMP 没有响应（超时或设备限流），请稍后重试` —— 一次都没应答（设备不通 / 被限流）
- `没有 LLDP / CDP / EDP 邻居（设备可能没开邻居发现协议）` —— 设备答了，但表里没有邻居

### 链路指标（带宽 / 上行 / 下行流量）

每条链接可以挂三组监控项，用来在连线中点显示实时指标：

| 项目 | 做法 |
|---|---|
| 选择方式 | 「链接」窗口里 **带宽 / 上行流量 / 下行流量** 各一个 `选择…`，打开监控项选择器；**完全由用户手工挑**，模块不做任何自动匹配 |
| 可选范围 | 只列**这条链路两端主机**的监控项，且只列**数值型**（`value_type` 0 浮点 / 3 无符号整数），把交换机模板上几百条 `net.if.alias` / `descr` 文本项滤掉；可按名称或 key 搜索 |
| 多选 | 每条可多选：链路聚合的多个成员口就是同一对设备间的多条线，各自勾各自的成员口监控项 |
| 取值 | 显示时取每个监控项的**最新值**（即监控项列表里的「最新数据」）后**求和**，再按单位换算 |
| 单位换算 | 单位含 `bps`（比特/秒）→ 直接按 `bps / Kbps / Mbps / Gbps` 格式化；单位是 `Bps` / `B/s` / `bytes` / `octets`（字节）→ 先 ×8 换成比特/秒；其它单位（`%`、`个`…）→ 原样显示「数值 + 单位」 |
| 渲染 | 连线中点自上而下：标签 → `≡ 带宽`（黄）→ `↑ 上行`（青）→ `↓ 下行`（绿）；取不到数据时显示 `-` |
| 存储 | `sysmaps_links` 只有 `linkid/sysmapid/selementid1/selementid2/drawtype/color/label` 七列，没有空余列，所以配置存在**模块自建表** `topomap_link_metrics`（`linkid` 主键 + `sysmapid` + `bw_itemids/in_itemids/out_itemids`，值为逗号分隔的监控项 ID）。表在 get / save 路径上 `CREATE TABLE IF NOT EXISTS` 懒建 |
| 保存时认领 linkid | `map.update` 不返回新链接的 `linkid`，所以保存后**回读一次**链接：原有链路按 `linkid` 直接对上，新建链路（数组里没有 `linkid` 的）在回读结果里「排除已有 id、按数值升序」依次认领 —— Zabbix 正是按 payload 数组顺序插入新链接的 |

### 连线走线（自动直角 / 手动折点）

「链接」对话框新增 **走线** 一栏，三种模式：

| 模式 | 效果 |
|---|---|
| 自动曲线 | 默认，和以前一样（单线是直线，链路聚合的成员线贴近成束） |
| 自动直角 | 按横 / 竖正交折线走（横向为主走「横-竖-横」，纵向为主走「竖-横-竖」），适合绕开设备图标和文字框 |
| 手动折点 | 点 **在画布上点选折点** 关闭对话框进入折点模式：**点击空白处加折点、拖动圆点调整、双击圆点删除、Esc 完成**，折点数量不限 |

链路聚合的多条成员线整组共用一份走线与折点（点任意一条都进同一个对话框）；画布平移、元素拖动导致内容整体位移时，折点跟着一起移动，绕行关系不变。保存前画布自动收紧时也会把折点算进内容范围。

走线配置存在模块自建表 `topomap_link_paths`（`linkid` 主键 + `sysmapid` + `routing` + `waypoints` JSON），和指标表一样懒建；`routing`：`0` 自动曲线 / `1` 自动直角 / `2` 手动折点。新建链路同样按 `new_seq` 认领 `linkid`；重新发现复用 `linkid` 时折点原样保留，被移除的链路配置随图删除一起清掉。

### 视图状态记忆（和原生一样）

原生 `map.view` 不带 `sysmapid` 时读的是用户 profile 里的 `web.maps.sysmapid`，
而列表页 `sysmaps.php` 打开时会 `CProfile::delete('web.maps.sysmapid')`；
左侧菜单「拓扑图」固定指 `action=map.view`，所以点菜单总能回到上次的视图。

本模块照抄这套做法：

- 打开某张图 → `topomap.data&mode=remember` 写 `web.topomap.sysmapid`
- 回列表 / 浏览器后退 → 同一个接口把它删掉
- 页面加载时控制器按这个 key 决定 `data-sysmapid`，前端据此直接进画布或留在列表
- 地址栏同步 `&sysmapid=N`，浏览器后退能从画布退回列表
- 图被删掉时自动回落列表，并顺手清掉脏记录

因为存在数据库的用户 profile 里，换浏览器、换设备、重新登录都记得。

### 主机状态（和原生拓扑图一致）

主机元素在预览时会叠加实时状态，**标签下方那行彩色文字**和原生拓扑图是同一套规则：

| 情况 | 状态行文字 | 颜色 | 图标 |
|---|---|---|---|
| 正常 | `正常` | `#009900`（`ok_unack_color`） | `iconid_off` |
| 有未恢复问题 | 只有一个问题 → 触发器名称；多个 → `N 个问题` | `#E45959`（`problem_unack_color`） | `iconid_on`，图标不可用时回落到 `iconid_off` |
| 已停用 | `已停用` | `#960000` | `iconid_disabled` + 置灰 |
| 在维护中 | `在维护中` | `#EE9600` | `iconid_maintenance` |

只在标签里写状态，**图标右上角不打问题数角标**（原生拓扑图也没有）。颜色不是写死的：后端从
`CSettingsHelper` 读全局「触发器显示选项」里的配置，取不到才用 Zabbix 默认值。

标签第一行显示什么由 `sysmaps.label_type`（开了「高级标签」则按 `label_type_host` 等）决定：

- `0` 自定义标签（`selements.label`）
- `1` IP 地址
- `2` 元素名称（主机名）
- `3` 只显示状态
- `4` 不显示标签
- `5` 自定义宏模板（本模块按标签文本回退显示）

### 画布尺寸与拖拽边界

元素坐标存在 `sysmaps_elements.x/y`，画布大小取自 `sysmaps.width/height` ——
这跟原生拓扑图是同一份数据。区别是**本模块不让你填死这个尺寸**：

- **打开时**：画布取「内容外接框（元素 + 形 + 60px 留白）」与「画布可视区域」中较大的那个。
  画布永远铺满整个可视区域，所以屏幕上任何一处都算画布，不会出现「右边这块不是画布、拖不进去」。
  以前存成 3000×3000 的大画布，也不会一进去就是满屏空白网格。
- **往右 / 往下拖**：拖出当前范围画布实时变大（`growCanvasTo`），**指针贴住画布边缘时视图还会
  自动跟着平移**（`autoPan`，边缘 56px 内每帧 16px），拖到窗口边上也不会「卡住不动」。
- **往左 / 往上拖**：`x/y` 不能为负（与原生编辑器同一份数据），所以走到 0 之后由 `shiftContent()`
  把**整张图往右下推**，被拖的那块贴回 0、视图反向平移 —— 屏幕上看起来元素没动，实际是**画布往
  左上长出来一块**。于是四个方向都没有边界。
- **窗口变化时**：`resize` 会把画布补到新的可视尺寸（只增不减，不会破坏已有内容）。
- **保存时**：先用 `contentMin()` 把内容整体贴回左上角（不留左上空白、绝不写负坐标），
  再按内容收紧到不低于可视区域，把最终宽高写回 `sysmaps.width/height`。
- 工具条上的 `自动 · 1720 × 856 px` 是当前实际尺寸，鼠标悬停有说明。
- 进入画布固定 100%（1 像素 = 1 像素）；内容比窗口大时点 **适应窗口**。

> 代价：如果你在原生编辑器里特意留了大片空白（比如给未来元素预留位置），
> 用本模块保存后画布会收到内容 / 可视区域大小。数据是共享的，这一点没有单独字段可存「自动 / 手动」标记。

## 已知限制（都是有意为之，不是 bug）

1. **与原生拓扑图共用数据**：模块建的图会出现在「监测 → 拓扑图」里，原生建的图也会出现在本列表里。
   好处是一份数据两个入口；如果你要完全隔离，需要另存一张表（改动较大）。
2. **图标映射（Icon map）不在预览里解析**：勾了「自动选择图标」时，属性照常保存（原生拓扑图会按图标映射取图标），
   但本模块预览统一显示「默认图标」，状态行与问题图标仍然正常。
3. **主机组 / 触发器 / 嵌套图元素**：可以预览、拖动、删除，但不能在属性窗口里编辑（会提示原因），
   状态行目前只对**主机**元素计算（主机组/触发器的聚合状态未做），要改请在原生拓扑图编辑器里改。
4. **标签类型 `5`（自定义宏模板 `label_string_*`）按标签文本回退**：预览不解析 `{HOST.NAME}`
   这类宏，原生会展开。其余 0/1/2/3/4 与原生一致。
4. **画布尺寸自动**（`sysmaps.width/height` 由内容推算，且不小于可视区域）：
   四个方向拖拽时扩展、保存时把内容贴回左上角并收紧。所以没有「手动输入宽高」的入口，也不会留下大片空白。
5. **保存是按 id 的差异更新**：`map.update` 拿 `selementid / linkid / sysmap_shapeid` 与库里比对，
   自己算出「新增 / 更新 / 删除」。前端提交的是画布上的完整状态，新元素用临时数字 id（`900000001` 起，
   必须纯数字，否则 PostgreSQL 下 `dbConditionId` 会因 bigint 与 text 比较直接报错），落库时由 Zabbix 换成真实 id。
   因此在模块里删掉的元素、形、链接会被真正删除 —— 提交什么就是什么。
6. **拓扑图名称必须唯一**：这是 `sysmaps` 的约束。重名时模块会直接提示「已存在名为…的拓扑图」，
   而不是交给 Zabbix 静默失败（见下方实测记录）。

## 实测记录（Zabbix 7.0.28 / CentOS 8 / nginx + php-fpm 8.2 / PostgreSQL）

部署到真机后修掉的三个问题，都记在这里，避免以后重犯：

1. **`Module.php` 里写 `APP::Component()` 会让菜单静默消失。**
   在 `namespace Modules\Topomap` 内部，`APP` 会被解析成 `Modules\Topomap\APP`；
   PHP 本来有「找不到就回退到全局类」的规则，但 Zabbix 的 autoloader 找不到会直接抛
   `Error: Class "Modules\Topomap\APP" not found`，回退不会发生 —— 而 `init()` 外层套了
   try/catch，异常被吞，表现就是「模块装好了、页面能开、菜单没有」。
   **必须写 `\APP::Component()`**（函数 `_()` 和常量没有这个问题，类名才有）。
2. **`map.get` 的 `selectSelements` 一旦指定 `output` 就必须显式列出 `selementid`。**
   漏了它，前端拿到的元素没有 id，保存时会把已有元素当成新元素重复插入。
   同理 `selectShapes` 要带 `sysmap_shapeid`，`selectLinks` 要带 `linkid`。
3. **7.0.28 的 `CMapElement::checkLinkInput()` 有个大小写笔误**：
   判断写的是 `$method == 'updateLink'`，而实际传入 `__FUNCTION__` = `updateLinks`，
   于是「更新链接」永远走「新增链接」的校验分支，要求每条 link 必须有 `sysmapid`。
   带 `linkid` 却不带 `sysmapid` 的链接会直接报 `Wrong fields for map link.`，整张图保存失败。
   模块在 `modeSave()` 里给带 `linkid` 的链接统一补上当前图的 `sysmapid` 绕开它（同时覆盖前端传值，防越权）。

另：页面标题要用 `CControllerResponseData::setTitle()`，往构造参数里塞 `title` 是取不到的
（`ZBase` 只读 `getTitle()`），否则浏览器标签只剩站名。

### 1.0.2 修的：弹层一进页面就糊在脸上、点「关闭」没反应

**现象**：点菜单进页面，屏幕上直接压着「选择主机」弹层；点 × 或「关闭」毫无反应。

**原因**：整页的显隐都靠 `el.hidden = true/false`，而 `hidden` 属性的隐藏效果来自浏览器的
用户代理样式 `[hidden] { display: none }`。本模块 CSS 里 `.tm-overlay` 和 `.tm-editbar`
写了 `display: flex` —— 作者样式的优先级**高于**用户代理样式，于是 `display: flex` 把
`display: none` 顶掉了，`hidden` 属性等于没写：

| 元素 | 被谁顶掉 |
|---|---|
| `#tm-overlay`（属性窗） | `.tm-overlay { display: flex }` |
| `#tm-host-overlay`（主机选择器） | `.tm-overlay { display: flex }` |
| `#tm-editbar`（编辑工具条） | `.tm-editbar { display: flex }` |

两个弹层都盖着，DOM 里靠后的主机选择器在最上层，所以看到的是「选择主机」。点关闭只是
把属性设回 true，视觉上什么都没变。

**修法（两条腿走路）**：

1. CSS 里加兜底规则，作用域限制在模块内，不污染 Zabbix 原生界面：
   ```css
   #topomap-root [hidden] { display: none !important; }
   ```
2. JS 里所有显隐改走 `setHidden(el, hide)`，同时写 `hidden` 属性和**内联** `style.display`。
   内联样式优先级高于任何作者选择器，即使浏览器缓存了旧 CSS 也照样生效。

**教训**：`hidden` 属性 + 自带 `display` 的类名 = 一定会踩的坑；jsdom 不计算样式，
冒烟测试测不出来，所以补了 `test/style_audit.js` 做源码层面拦截。

### 1.0.3：列表页对齐原生 + 画布 100% + 尺寸可改

**界面**：照 `include/views/monitoring.sysmap.list.php` 重做列表页，结构直接复刻原生
（`header.header-title` + `filter-space` + `list-table` + `action-buttons`），只用自己的 JS 驱动。
另外补了名称过滤、表头排序、全选/批量删除、JSON 导出。

**画布**：进入时不再自动缩放（原来 `openMap()` 里调了 `fitView()`），改为固定 100%；
`100%` 按钮重新定义为「回到 100%」，新增「适应窗口」按钮。宽高可在新建和「属性」里改。

踩到的三个坑：

1. **`layout.htmlpage` 只输出 `<div class="wrapper">` + `main_block`，不产出 `<header>` / `<main>`。**
   所以模块页本来没有标题栏和右上角按钮区。页头和 `<main>` 要在视图里自己写，样式靠主题的
   `header{}` / `main{}` 规则接管（`header` 是 45px 白底、`.header-controls` 用 `margin-left:auto` 靠右）。
2. **`getInput()` 只认 `validateInput()` 声明过的字段。** 新增 `width` / `height` / `sysmapids` 时

   导出把全部图都导了出来。**控制器里加参数，必须同步 `validateInput`**（这个坑很安静，不报错）。
3. **7.0.28 的 `map.create` 遇到重名会 `return false`，不抛异常。** 模块拿到 `false` 后
   `(string) $result['sysmapids'][0]` 得到空字符串，前端 `openMap('')` 才报「缺少有效的拓扑图 ID」，
   真正的失败原因（重名）完全看不见。现在 `modeCreate()` 先查同名给出明确提示，再兜底「没有返回 ID」。

### 1.0.4：画布尺寸自动 + 画布区铺满窗口

**问题**：图上只有两个元素，画布却是 3000×3000，画布区下方还留着一大片空白。

**原因**：两处都写死了。

1. `.tm-canvas-wrap { height: calc(100vh - 235px) }` —— 235px 是估的。
   页头 45 + main padding 20 + 工具条 40 + 页脚，实测下来往往比 235 小，
   于是画布区到不了底，下面是纯背景色。
2. 画布宽高来自 `sysmaps.width/height`，新建时写死 1000×700，属性里又能手填成 3000×3000。
   尺寸一旦大了，元素全挤在左上角，其余都是空网格。

**修法**：

- 容器高度改由 `layoutCanvasWrap()` 实测：`视口高 − 容器顶部偏移 − 页脚高 − 12`，
  在打开画布、切换编辑模式、`resize` 时各算一次，写成内联 `height`。
  CSS 里只留 `calc(100vh - 200px)` + `min-height` 兜底。
- 画布尺寸改成内容驱动：
  - `contentExtent()` 取所有元素（含图标尺寸与标签高度）和形的右下角；
  - `growCanvasTo()` 在拖拽 / 新增时只在需要时向右下扩展，不设死边界；
  - `autoSizeCanvas()` 在打开和保存时按 `内容 + 60px` 收紧，下限 1000×700；
  - `saveMap()` 把算好的 `width/height` 一起提交，后端 `modeSave()` 钳到 100–10000 后写库。
- 创建弹窗和「属性」弹窗里的宽高输入去掉了，改为只读的「自动（当前 1200 × 800 px）」。
- 工具条改成 `自动 · 1200 × 800 px`。

**注意**：`sysmaps` 没有「自动 / 手动尺寸」这种字段，所以这个「自动」是每次打开/保存时现算的，
不落任何标记。原生编辑器里留的空白，用本模块保存后会被收紧。

### 1.0.5：画布铺满可视区域 + 拖到边缘自动平移

**问题**（用户反馈）：「主机拖拽还是受限画布的高度和宽度」。

**原因**：1.0.4 只做了「往右/下拖就长大」，但画布的**下限还是 1000×700**。
视口 1600×900 时画布只有 1000×700，右边和下边一大片区域根本不属于画布；
拖到 1000 处元素就顶住，再往外虽然会扩展，但 `.tm-canvas-wrap` 是 `overflow: hidden`，
元素立刻跑到视口外看不见 —— 手感上就是「被画布宽高卡住了」。

**修法**：

- `canvasMinSize()`：画布下限从写死的 1000×700 改成 `max(1000, 画布可视区域)`，
  画布永远铺满可视区域。屏幕上任何位置都在画布内，边界落到看不见的地方。
- `ensureCanvasFitsViewport()`：打开画布、切换编辑态、`resize` 时补到新的可视尺寸（只增不减）。
- `autoSizeCanvas()` 收紧时也取 `max(内容 + 60, 可视区域)`，保存下来的尺寸不会小于可见区域。
- **拖动改成地图坐标 + 贴边自动平移**：
  - `pointerToMap()` 按当前 `panX/panY/zoom` 反推地图坐标，`grabX/grabY` 记住抓取点，
    缩放或平移时元素也不会脱离指针；
  - `autoPan()`：指针进入边缘 56px 内，每次 `mousemove` 平移视图 16px，元素跟着继续走，
    不用松手再去拖空白处；左/上方向只在已经移出视口（`panX/panY < 0`）时回收，
    保证画布左上角不会离开视口左上角。
  - 元素 / 形的拖拽共用这套逻辑。
- 画布还没布局出来（`rect` 宽高小于边缘阈值）时 `autoPan()` 直接返回，
  否则 jsdom 这种没有布局的环境会一直往一个方向漂。

**验证**：`smoke.js` 新增 6 项（画布铺满 1400×700、元素拖到 x>1000 / y>400、
贴边时 `transform` 出现负平移、点 `100%` 复位）；`real_e2e.js` 在真页面把视口打成 1200×758，
确认 stage 尺寸与落库尺寸都变成 1200×758。

### 1.0.6：左、上方向也能拖（整图外推）

**问题**（用户反馈）：「是往左和往上受限」。1.0.5 解决了右边和下边，但 `x/y` 到 0 就停 ——
左/上还是一条硬边界。

**难度**：`sysmaps_elements.x/y` 不能为负（原生编辑器同样不允许，且这份数据原生视图也会读）。
所以不能简单地让坐标变负 —— 那样元素会跑到画布外，原生视图里直接看不见。

**修法**：`shiftContent(dx, dy)`

- 当拖到 `nx < 0`（或 `ny < 0`）时，把**所有元素和形**的坐标同加 `(dx, dy)`，画布宽高同量增加；
- 同时 `panX -= dx * zoom`、`panY -= dy * zoom`，视图反向偏移 —— 屏幕上原本画着的东西**原地不动**，
  效果就是「画布往左上长出来一块」，指针可以一直往外拖；
- 拖拽中的元素单独赋 `x = 0`（贴回边界），被推走的是**其他**内容，所以观感是它停在了画布左上角；
- `autoPan()` 里原来的「左/上边缘回收」删掉了 —— 那个逻辑会和平移互相打架。

配套改动：

- `drawShapes()` 改成幂等（先清 `.tm-shape` / `.tm-shape-text` 再画），
  这样 `shiftContent()` 能单独重画形，不用走 `paintCanvas()` 重建元素 DOM（否则拖拽中的节点引用会失效）；
- 新增 `syncElementNodes()`：只改 `.tm-el` 的 `left/top`，保住拖拽引用；
- 保存前用 `contentMin()` 把内容**整体贴回左上角**（`se.x -= minX`），
  否则往左/上拖过之后画布左边会留一块空白；同时 `pan` 反向补偿，画面不跳；
- 最终落库的坐标永远 `>= 0`，原生编辑器打开完全正常。

**验证**：`smoke.js` 新增 10 项（往左上拖到 -3000 后画布变大、元素贴 0、其他元素整体右移、
`transform` 出现负平移、保存载荷 min x/min y = 0 且全非负）；
`real_e2e.js` 新增 4 项，真机拖到负坐标后落库尺寸 ≥ 可视区域、元素坐标非负。

### 1.0.7：主机状态行（正常 / 问题 / 已停用 / 在维护中）

**问题**（用户反馈）：「没有主机状态吗？zabbix 自带拓扑图预览时会显示正常，有问题也会显示。」

**原因**：只做了图标和角标，**没做原生标签里的第二段文字**。抓原生 `map.view` 的渲染数据才看清：

### 1.0.9：自动发现连线绿底红警 + 自动关联端口状态触发器

**用户反馈**：自动发现的连线颜色改成正常绿 `00CC00`、报警红 `DD0000`，并自动关联触发器。

**做法**（用 Zabbix 原生的「链路指示器」机制，不自己造轮子）：

- **正常绿**：`modeDiscoverSave` 建的连线 `color = 00CC00`（原来是灰 `5B7C8D`）。
- **自动关联**：生成时按「端口名 + 状态类关键词」在链路两端主机上匹配触发器
  （`matchLinkTriggers`，源端优先、命中即只用源端），匹配到的写成连线的
  `linktriggers: [{triggerid, drawtype: 0, color: 'DD0000'}]`。
  这样**原生拓扑图**（监测 → 拓扑图）打开时也会按触发器状态自动把线画红。
- **自绘画布同样呈现**：`modeGet` 读回绑定关系，再查一次 `problem.get` 标出哪些触发器正在
  报警（`problem: true`），`topomap.js` 的 `drawLinks()` 据此把线画成触发器色
  （`linkProblemColor()`），否则用连线自身颜色。
- **保存不丢**：`sanitizeLinks` 透传 `linktriggers`，前端保存 payload 也原样回写，
  避免普通保存（`map.update`）把绑定关系冲掉。

**真机验证**（Zabbix 7.0.28，本地已部署到测试机后实测）：

```
map.create links[].linktriggers        -> 落库成功
map.update links[]（需带 sysmapid）    -> linktriggers 保持
map.update links[]（不带 sysmapid）    -> "Wrong fields for map link."（7.0.28 老 bug，模块已规避）
```

**坑（7.0.28 的 CMap.php 实测）**：`linktriggers` 是 **`selectLinks` 的嵌套字段**，不是独立的
`selectLinkTriggers` 选项 —— 源码里就是 `outputIsRequested('linktriggers', $options['selectLinks'])`。
所以 `modeGet` 的 `selectLinks` 只能给 `'extend'`：写死字段列表会被当成 `sysmaps_links` 的列去查，
返回空（或报未知字段），`selectLinkTriggers` 在这个版本更是不起作用。

**三处验证**：

1. 真机端到端（`discover_e2e.py 10764`）：3 条链路全部 `00CC00`、都带 `linktriggers`，
   自动匹配到 2 个端口状态触发器（`ge0_0_23` / `ge0_0_24` 各一个，描述里含「处于关闭状态」）。
2. `problem: true` 路径：把一条**正在报警**的触发器绑到临时图，模块 `mode=get` 正确返回
   `problem: true`（未报警时为 false）。
3. 浏览器目视（`zabbix.php?action=topomap.view&sysmapid=...`）：报警链路画成 `#DD0000`，
   普通链路画成 `#00CC00`，控制台无报错。

`smoke.js` 新增 3 项断言：报警的连线画成 `#DD0000`、未绑触发器的新连线保持本色、发现链路上带源/目标端口。

### 1.0.10：修「一台设备都发现不了 / 转很久」+ 支持 EDP + 未纳管设备

**用户反馈**：`开始发现：1 台起点，深度 2，协议 LLDP`，扫「机房办公交换机」过了很久一台设备都没出；
要求补 EDP；「包含未纳管的设备」勾了也没用。

**根因**（逐 OID 单独进程实测得到）：`scanLldp` 当时是「一次 walk 整棵 `1.0.8802.1.1.2.1`」，
而该子树下的 `lldpExtensions`（`1.0.8802.1.1.2.1.5`，LLDP-MED）会让这台 H3C S5560S（Comware 7）
的 agent 在 GETBULK 下**永久挂死**：

| 做法 | 结果 |
|---|---|
| `snmp2_real_walk('1.0.8802.1.1.2.1')`（模块当时的做法） | **挂死**，`timeout -s KILL 30` 都杀不出结果 |
| `snmp2_real_walk / snmp2_walk` 各窄表 | 53～527ms，全部正常（remTable 144 行 / 0.53s） |
| `snmpwalk / snmprealwalk`（PHP 的 v1 GETNEXT 变体） | 该设备根本不答 SNMPv1，一律在 timeout 后返回 false |

`modeDiscover` 的 20s 预算只在「扫下一台主机之前」检查，拦不住一个卡在 C 调用里的 walk →
整个请求被拖死，界面就停在「扫描 机房办公交换机 …」。

**修法**：

1. `scanLldp` 改成分表 walk（只走 remTable / locPortId / locSysName / manAddr 四张窄表），
   并把列号对齐标准 `lldpRemEntry`：原来的自研映射整体错了一位，`chassis` 拿到的是
   `lldpRemPortIdSubtype` 这个整数；邻居端口也改用 `lldpRemPortId`，只有它是 MAC（终端网卡）
   时才回落到 `lldpRemPortDesc`。
2. 显式 `snmp_set_oid_output_format(SNMP_OID_OUTPUT_NUMERIC)`：默认输出的
   `IF-MIB::ifName.7` / `iso.0.8802…` 混排会把多段索引（EDP 的 `<ifIndex>.<邻居id>`）截断，解析必错。
3. 新增 **EDP**：`EXTREME-EDP-MIB extremeEdpNeighborTable`（`1.3.6.1.4.1.1916.1.13.2.1`），
   邻居名取列 3、邻居端口取列 6，本地端口用 IF-MIB `ifName` 把索引里的 ifIndex 换成接口名；
   弹窗协议栏加 EDP 勾选框，后端协议白名单加 `EDP`。
4. 前端每批 `discover` 请求加 45s 超时（`withTimeout`），真卡住时报「扫描超时」而不是一直转。

**真机验证**（同一台「机房办公交换机」，hostid 10762 / 192.168.40.253 / SNMPv2c）：

```
单台主机、LLDP+CDP+EDP                    -> 0.94s，11 个邻居（原来永久挂死）
5 台一起（10762/10763/10764/10766/10773） -> 16.4s，5 台全部返回邻居（11/29/5/12/4）
discover_e2e.py 10762                     -> 全部通过（连线 00CC00、自动绑 4 个端口状态触发器）
discover_e2e.py 10764                     -> 全部通过（回归：3 条链路 / 3 个触发器）
浏览器勾 EDP + 包含未纳管设备             -> 约 5s 完成，日志
     「发现完成：31 台设备、30 条链路，其中 20 台已在 Zabbix 里，11 台为未纳管设备」，控制台无报错
```

**「包含未纳管设备」为什么之前「没用」**：这个开关本身是好的（勾上后匹配不到 Zabbix 主机的邻居
会以图片元素入图），是后端先挂死、一个邻居都没读出来，自然什么都画不出来。修掉挂死后浏览器
实测一次就带出 11 台未纳管设备。

### 1.0.11：同一对设备多条连线 + 每条连线可选带宽/上行/下行监控项

**需求**：链路聚合时多个成员口对端是**同一台主机**，要能生成多条连线；每条连线要能显示
**带宽 / 上下行流量**。数据来源由用户自己从 Zabbix 监控项最新值里挑，不做自动匹配。

**做法的三处差距**（对照 `f:\bbb\aiops`）：

1. **连线去重键**：原来前后端都按「设备对」去重，同一对设备只能有一条线 → 改成按
   「**两端端口**」的无序键去重（`设备#端口` 两端排序后拼接）。这样 N 个聚合成员口生成 N 条线，
   而 LLDP 双向发现报的是同一对端口、仍会被合并成一条；端口为空时退化成设备对，与旧行为一致。
2. **指标存储**：`sysmaps_links` 只有七列、没有空余列，所以新增模块自建表 `topomap_link_metrics`
   （`linkid` 主键 / `sysmapid` / `bw_itemids` / `in_itemids` / `out_itemids`），
   在 get / save 路径 `CREATE TABLE IF NOT EXISTS` 懒建。
3. **保存后认领 linkid**：`map.update` 不回传新链接的 `linkid`，于是保存后**回读**一次链接：
   原有链路按 `linkid` 直接对上，新建链路用前端给的 `new_seq`（在 links 数组里的出现顺序）
   在「回读结果排除已有 id、按数值升序」里依次认领，再写指标表。

**前端**：「链接」窗口加 **带宽 / 上行流量 / 下行流量** 三行，各带 `选择…` / `清空`；
`选择…` 打开监控项选择器（只列这条链路**两端主机**的**数值型**监控项，可搜索、可多选）；
画布连线中点自上而下画：标签 → `≡ 带宽`（黄）→ `↑ 上行`（青）→ `↓ 下行`（绿），
值取所选监控项**最新值之和**，单位按 `bps` / 字节 / 其它三类换算。

**新增后端接口**：`mode=items`（给一批 hostids + 关键字，返回数值型监控项及其最新值）。

### 1.0.12：本地端口名回退 + 同对元素多条连线错开 + 触发器来源端可选

**需求（真机反馈）**：① 核心交换机的本地端口在连线上显示成 `65547` 这种数字，导致同一对
设备的多条线合不掉、触发器还关联到了对端；② 链路聚合的多条连线在画布上完全重叠、「只看到
1 条」；③ 要在链接属性里能选「触发器来源端」。

**根因**：`lldpRemLocalPortNum` 在 Comware 上是「**槽位 << 16 | 端口号**」，本模块原来靠
`lldpLocPortId` 换可读名；但最忙的核心交换机（29 个邻居，前面几次 walk 已把 snmpd 打到限流）
这一步回了**空表**，本地端口就退化成原始数字。原始数字与对端报的 `Gi1/0/11` 归一化后不相等，
于是双向重复线合不掉（视觉上重叠成一条），按端口匹配触发器也匹配不到源端 → 回退到对端。

**做法**：

1. **本地端口名回退**（`LldpDiscovery`）：`lldpLocPortId` 空表要**复测一次**（限流时设备会回
   空表）；仍取不到时按需 walk 一次 `IF-MIB ifName`（把 Comware 编码端口号当 ifIndex 查）；
   再不行才用 `槽位<<16|端口号` 解码成 `GigabitEthernet{槽}/0/{端口}`；最后才回退原始数字。
2. **去重键端口归一化**（前后端 `ifPortKey` 同规则）：`Gi1/0/11` / `GigabitEthernet1/0/11` /
   `ge1_0_11` 归一后都是 `ge1011`，双向重复合并、LAG 多成员口各自成线。
3. **同对元素多条连线错开画**（`drawLinks`）：按「元素对」分组，组内给每条线一个对称的垂直
   偏移，画成**二次贝塞尔曲线**（单条线偏移 0 = 仍是直线），标签落在曲线中点，不再完全重叠。
4. **触发器来源端可选**：链接属性新增「**触发器来源**」下拉（自动（源端优先） / 仅源端 /
   仅本端 / 两端都关联 / 不关联），随链路落库（模块自建表新增 `source_port` / `target_port` /
   `trigger_source` 三列，老表自动 `ALTER` 补列）。改完点「应用」会调 `mode=linkTriggers`
   立刻按新口径重新匹配一次；**只改标签/颜色不会动触发器**，避免冲掉手工绑定的触发器。
5. **连线上标注两端端口**：连线中点最上面一行画 `源端端口 → 本端端口`（9px 灰字），
   链路聚合时用来区分同对设备的多个成员口。

**新增后端接口**：`mode=linkTriggers`（给两端 hostid + 端口 + `trigger_source`，返回命中的端口状态类触发器）。

**排查记录**：用户反馈的「带宽/流量选择没反应」经浏览器实测**无法复现**（监控项选择器正常
打开、搜索 `icmp` 返回 6 条、控制台无报错）。判断为多条重复线完全重叠导致「改了哪条看不出来」，
第 3 条修复后应一并消失。

### 1.0.14：修正自动发现的 IP / 主机名 + 去掉连线端口标注 + 聚合连线整组可编辑

**需求（真机反馈）**：① 自动发现生成的图里「好几个 IP 和主机名称都不对」（多台设备显示成同一个
`192.168.1.1`，还有一堆只有 IP 没有名字的节点）；② 连线上那句「源端口 → 本端端口」不需要显示；
③ 链路聚合的多条连线**不需要每条都能编辑**，要像 aiops 那样整组当一条链路。

**做法**：

1. **IP / 名字修正**（`services/LldpDiscovery.php` + `actions/TopomapData.php`）：
   - `lldpRemManAddr` 改为按 **`(timeMark, 本地端口, remIndex)` 完整索引**关联地址（原来只按本地端口，
     同一端口下多条 rem 条目会互相覆盖、地址张冠李戴），取不到再回退按端口。
   - **匹配到 Zabbix 主机时显示主机自己的管理 IP**（`discoveryIndex()` 里补出 `ip`），
     不再显示 LLDP 邻居上报的地址 —— H3C 会把本机管理地址回声进所有端口的 `lldpRemManAddr`，
     这正是「一堆设备都显示 `192.168.1.1`」的根因；同时也按 `sysName` 反查主机名。
   - **丢弃「地址回声」**：同一台设备上报的邻居里，若同一个 IP 出现在**多个不同设备名**的邻居上，
     说明这不是邻居地址（IP 是设备的唯一标识），整批判为无效。
   - **丢弃无名邻居**：未匹配到主机、又没有 `sysName` 的条目不再生成节点（原来会退化成
     「名字 = IP」的幽灵节点，和已纳管节点重复出现）。
2. **连线不再标注端口**：删掉连线标签框里的 `源端口 → 本端端口` 那一行（`tm-link-port`）；
   端口信息只保留在「链接」对话框里，聚合时列出**全部成员口**。
3. **聚合的多条连线 = 一条可编辑链路**（对齐 aiops）：同一对元素之间的所有连线由 `linkFamily()`
   归为一组 —— 线还是按成员口画多条贴近成束的曲线，但**整组共用一个标签框**（画在中间那条线上，
   并单独叠在徽标层里，避免后画的成员线从框中间穿过）；**点任意一条都打开同一个「链接」对话框**，
   标签 / 颜色 / 线型 / 触发器来源**一次改完整组**，指标只挂在组里第一条线上（整组共用一份，
   显示时仍按成员口求和）；移除模式点任意一条即删掉整组。

### 1.0.19：主机状态按原生口径过滤禁用触发器

**需求（真机反馈）**：主机元素上的问题数比 Zabbix 自带拓扑图多 —— 核心交换机自带图显示 1 条，
模块显示 2 条。

**原因**：模块原来直接用 `problem.get?hostids=...` 拉未恢复问题。触发器被禁用（`status=1`）后，
它残留的未恢复问题仍在问题表里（`r_clock=0`），于是被多算一条；原生 `getSelementsInfo()` 只认
「启用 + 受监控 + 当前处于问题态」的触发器。

**做法**（对齐原生）：

1. 先 `trigger.get`，条件 `filter: {state: null}` + `monitored: true` + `only_true: true`
   （value = PROBLEM）+ `skipDependent: true`，拿到真正在报且在监控的触发器；
2. 再用这些 `triggerid` 去 `problem.get`（不带 `recent`，只数未恢复），按触发器挂到主机上计数；
3. 连线触发器同样只认启用状态（原生 `CMapHelper` 要求 `status == TRIGGER_STATUS_ENABLED`），
   禁用触发器残留的问题不会把连线染红。

真机核对：核心交换机 `problem.get?hostids` 返回 2 条，其中 `34143`（端口关闭）`status=1`；
原生口径触发器 1 条；模块 `mode=get` 该主机元素 `problems=1 / severity=1`，与自带拓扑图一致。

   同一口下挂的 3 台 / 5 台终端会挤成一条；改为「(sysName，空则 chassisId) + 本地端口」。
3. **H3C 端口 MAC 当接口名的问题**：部分端口在 `lldpLocPortId` 里报的是端口 MAC
   （`70:81:85:2C:05:E1`），现在识别为不可读名并回退 `IF-MIB ifName`，
   连线上显示 `GigabitEthernet1/0/12`，端口触发器也能正常匹配。
4. 前端节点键同步用 `sysName || chassisId || IP` 兜底，未纳管节点按 chassis 独立成节点。

真机验证（机房办公交换机 `192.168.40.253`，深度 1）：邻居数 **5 → 20**，
`1/0/12` 的 3 台终端、`1/0/22` 的 5 台终端各自成节点。

### 1.0.25：预览模式点主机弹原生主机菜单

1. 预览模式下单击主机图标（含主机标签），弹出与 Zabbix 自带拓扑图完全相同的主机菜单。
2. 菜单数据直接取 Zabbix 自带的 `menu.popup`（type=host），再用原生 `getMenuPopupHost` +
   `$.fn.menuPopup` 渲染，因此分段、措辞、权限判断、禁用态与自带拓扑图一致：
   **视图**（仪表盘 / 问题 / 最新数据 / 图形 / Web监测 / 资产记录）、
   **配置**（主机 / 监控项 / 触发器 / 图形 / 自动发现 / Web监测）、
   **链接**（第三方模块注入的 View Neighbors (LLDP/CDP)）、
   **脚本**（Detect operating system / Ping / Traceroute）。
3. 菜单项跳转到对应的原生页面并带 `hostids` 过滤；「配置 → 主机」打开原生 `popup.host.edit`
   弹窗（模块页没有地图页的 `view.editHost`，改为直接调 `PopUp`）。
4. 图片、主机组、触发器等非主机元素不弹主机菜单；出错时在页面内提示，不打断画布。

### 1.0.24：形与 Zabbix 自带拓扑图完全对齐

1. **三种形**：矩形 / 椭圆 / **线**。线的 `x,y` 是起点、`width,height` 是终点绝对坐标，
   渲染成 SVG `<line>`，与原生 `sysmap_shape` 的语义完全一致（线不画文字、不填背景）。
2. **属性窗口照抄原生**：「拓扑图形状」标题；形是三段按钮（矩形 / 椭圆 / 线）；
   文本；字体（Helvetica 等 13 种，下标与原生一致）、字体大小、颜色；
   横向 / 纵向对齐（居中 / 左 / 右、居中 / 上 / 下）；背景颜色；
   边框类型 / 宽(px) / 颜色；坐标 X/Y；大小 宽(px)/高度(px)；按钮 应用 / 移除 / 关闭。
   切到「线」时自动收起文本与背景行，标签换成原生的 线 / 点 / X1、Y1 / X2、Y2，
   坐标按原生规则在「外接框 ↔ 两个端点」之间换算。
3. **文字与边框细节对齐**：字体族按原生 `SVGMap.FONTS` 渲染（font=9 显示 Helvetica、实际画
   Trebuchet MS），内边距 5px，文字按多行拆分并裁剪在形内部；点线 / 虚线的 dash 数组随线宽放大
   （`1,2` / `4,4`，线宽 > 2 时点线用圆头），边框类型 0 时线宽为 0。
4. **鼠标拖动改大小**：单击形选中，出现与原生一致的 **8 个 7×7 圆形控制点**
   （四角 + 四边中点，白底、1px 深蓝描边；深色主题自动换成深底浅边），拖控制点改
   `x/y/宽/高`，矩形/椭圆最小 1px；选中线时是 **2 个端点圆点**，拖端点改起点 / 终点。
   双击形打开属性窗口，点空白处取消选中。
5. 新建形的默认值与原生一致：`10,10` 起、`50×50`、黑色实线 2px、Helvetica 11 号黑字。

### 1.0.23：自动发现树形布局的连线

1. **锚点下移**：上下两层的连线，从父节点「图标 + 名称 + 正常 / 问题」文字块**下方 6px**
   接出（不再是图标底边），落到子节点图标顶边上方 6px；标签文字多行（多行主机名、
   多条问题）时锚点跟着往下让。同一层/左右相邻的连线仍按元素中心直连。
2. **1 台下属走直线，多台自动直角**：一个父节点下只有 1 台「设备」时直接连一条直线
   （链路聚合的两个成员口也仍然只是直线，不因为成员口多就拐弯）；
   多台时先竖直走到父锚点下方 30px 的共用主干，横向分到各子节点正上方，再竖直落下。
3. **横向主干不贴图标**：树形布局的层间距从 180 加到 **300**，主干落在父节点文字块下方，
   离子节点图标顶还有 100px 以上 —— 这段竖直空间用来竖着放子节点的带宽 / 流量框。
4. **带宽 / 流量框居中在子节点那根竖线上**：树形直角的连线，指标框不再落在走线中点（会压在横向主干上，
   看不出属于哪台主机），而是水平居中在子节点正上方、纵向落在「主干拐点 → 子节点图标」这段竖线的
   **中点**；子节点下移、层间距变大时线变长，框自动跟着居中（和 Zabbix 自带拓扑图一致）。
5. **指标框边框跟随连线颜色**：正常链路绿框（`#00CC00`），该链路的触发器报警 / 端口断开时变红框
   （`#DD0000`），和线本身同一个颜色取值，一眼能对上。
6. **链路聚合平行线**：同一对元素的多个成员口，**两端按同样的偏移并排**（间距 12px），
   画成平行的竖线 + 平行的横段，两端不再收成一个尖点；各成员的主干上下错开一个线间距，
   不会重叠成一条线。整束偏向子节点一侧，避免横穿「正下方那台主机」的竖线。
7. **自动发现的连线默认「自动直角」**：发现时写了两端端口名的链路直接走树形布线，
   不用逐条去「链接」对话框里改；手工连的线仍默认「自动曲线」。
8. 「自动曲线」也落库（`topomap_link_paths`）：改成自动曲线后不会再被默认值渲染回自动直角。
9. 成员口仍**各自按自己的端口匹配触发器**，一条成员口进问题状态只红这一条，不整组变红。

> 已有自动发现的图要看到新间距，点画布上的「重新发现」→ 布局选「全部重排成树形」即可
> （设备 / 链路 / 端口 / 触发器配置都会保留）。

升级后浏览器请 **Ctrl+F5** 强刷一次。
